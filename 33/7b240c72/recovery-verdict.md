## Boundary and method

- **Stub:** `scripts/stub/systemctl`. I wrote it independently of `cli/test/stubs/systemctl`, which I also inspected and consider sound.
  - It records the exact argv, a sequence number, which unit files exist on disk, and optionally whether watched pids are alive at the moment of each call. This is observation only.
  - It models unit-file presence, enablement and activity, with the timer's enablement kept separate from the tick service's activity, and returns the `show` output shapes the adapter parses.
  - It injects `once:` or permanent failures on an exact argv, and it rejects any other verb or shape with exit 64.
  - It never fires a timer, runs a unit or signals a process.
  - Each probe's PATH is only `<stub>:<node dir>:/usr/bin:/bin`, and the host has no `systemctl`, so no call could reach a real manager.
- **Real Factory code:**
  - The CLI is `cli/bin/factory.mts`, run as a subprocess from the checkout. `factory install` copies the app, and the tick runs from that installed copy.
  - Ticks are launched exactly as the generated `factory-tick.service` would run them. The probe parses `ExecStart` and `Environment=` from the unit with systemd's documented quoting rules (`lib.mts parseService`), then runs only those, with stdin `/dev/null`, cwd = HOME and its own session.
  - Process trees are real:
    - a dispatcher holding a nested non-detached shell;
    - a nested "analysis" node process with its own child;
    - a detached ticket run in its own session that writes a run record of the shape `reserveRun` produces;
    - bystanders: an own-session `sleep`, a `sleep` in the verifier's own process group, and an unrelated node process.
- **SIGTERM stand-in:** S3-B sends SIGTERM to the tick myself, standing in for the documented effect of `systemctl stop` under `KillMode=process`. That is labelled wherever it is used. Everywhere else, the signals come from Factory's own `schedule off`, `uninstall`, `install` and tick code.
- **The one in-process probe (F7)** replaces only the signal sender, via `CancelOptions.kill`, so that a cancellation cannot be confirmed. It calls the production `schedule('off')` and `uninstall()` with the real adapter and the stub.

## Accepted deviations, not defects

- **Traversal is wider than the ticket's "first enabled project".** The tick visits every opted-in project in registry order and stops at the first manager gate or cancellation. This is safety-equivalent: no later work after off (S3A.11, F9.4). Rotation is #34. review-0 accepted it.
- **The interface shapes follow the merged #31/#32 code,** as the user instructed:
  - `ScheduleBackend.install(spec, record)` and `status()` returns `{timer, enabled, tick, lastTick?}`.
  - The opt-in protocol check uses #32's actual `reserveRun` interface, since there is no `schedule-protocol=1` marker or exit code 78.
  - `FACTORY_SCHEDULED=1` is passed, but the current dispatcher ignores it.
  - `readScheduleStatus` and `timings.json` are not separate here: the full status contract is #37 and timing history is #36.
- **Leftover cleanup.** When a pass's leader exits while non-detached members of its group are still running, the tick terminates that group alone (SIGTERM, grace, SIGKILL) and records the reason. S4B shows this: the 45 s holder left its background children, and the reason reads "left processes running in its process group, terminated". This is cleanup after the pass has ended, not a timeout on a running pass. review-0 to review-2 accepted it.
- **Cosmetic:**
  - A pass killed by a signal is recorded as `exitCode: 128`, not 128+signal (S3A.10).
  - `TimeoutStopSec=2min` is a stop-only bound on systemd's wait for the tick's own cancellation (30 s grace, 5 s confirm, 2 s margin). It is not a start or pass timeout.

## Trusted third-party semantics (not proven here)

- systemd firing and rearming the timer: `OnActiveSec`, `OnUnitInactiveSec` after success or failure, and `Persistent=false`.
- `systemctl stop` sending SIGTERM to the tick's main process under `KillMode=process` and waiting up to `TimeoutStopSec`.
- `disable --now` preventing further activations.
- journald storage.
- The default `StandardInput=null`.
- The default user-unit working directory.
- `XDG_RUNTIME_DIR` being available so the tick's own `systemctl --user show` can work inside the service. If it were not, the tick would see `unknown` and fail closed (F8, M).
- The documented unit-file quoting, specifier and `$` rules that my parser implements.

No stub output is presented as a real timer or journal observation.

## Factory-owned behaviour not verified here

So a tick from such a home cannot run. This is outside the ticket's listed characters (spaces, quotes, percent, dollar) and is not a Factory quoting defect. A newline in a path is also outside scope and untested.
